Fix: "Not Secure" on https://localhost:4200 (ng serve HTTPS cert)

This guide fixes the case where the browser shows "Not secure" with https crossed out on https://localhost:4200, even though ng serve --ssl is running. This also blocks things that require valid HTTPS, like Facebook Login's JavaScript SDK.

Why it happens

Angular's dev server uses SSL cert files exported from the ASP.NET Core dev certificate, located at:

%APPDATA%\ASP.NET\https\<npm_package_name>.pem
%APPDATA%\ASP.NET\https\<npm_package_name>.key

The script that creates these (aspnetcore-https.js, run via npm run prestart) only generates them if they don't already exist. If old/untrusted cert files are already sitting in that folder, they never get refreshed automatically — even after re-running dotnet dev-certs https --trust.

Step 1: Clean and re-trust the dev certificate

Open a command prompt and run:

dotnet dev-certs https --clean
dotnet dev-certs https --trust

Accept the Windows security prompt to trust the new certificate.

Step 2: Delete the stale exported cert files

These are the files ng serve --ssl actually uses, and they won't regenerate on their own:

del /q "%APPDATA%\ASP.NET\https\*.pem"
del /q "%APPDATA%\ASP.NET\https\*.key"

Step 3: Full restart

  • Fully close all browser windows (not just the tab) — Chrome caches HTTPS/certificate state per-session.
  • Fully stop your dev server (Ctrl+C in the terminal, or Stop Debugging in Visual Studio).
  • Restart it — this re-runs npm run prestart and regenerates fresh .pem/.key files from the newly trusted certificate.
  • Open a new browser window and go to https://localhost:4200 — you should see a padlock instead of "Not secure".

All-in-one script

Save this as fix-https-cert-full.bat and run it whenever this comes back:

@echo off
echo ===================================================
echo  Full HTTPS dev certificate reset for localhost
echo ===================================================

echo.
echo Step 1: Removing any existing dotnet dev certificates...
dotnet dev-certs https --clean

echo.
echo Step 2: Deleting old exported cert files used by Angular's ng serve...
del /q "%APPDATA%\ASP.NET\https\*.pem" 2>nul
del /q "%APPDATA%\ASP.NET\https\*.key" 2>nul
echo    (Old .pem/.key files removed, if any existed.)

echo.
echo Step 3: Creating and trusting a brand new dev certificate...
dotnet dev-certs https --trust

echo.
echo ===================================================
echo Done! Now fully close your browser, restart your dev
echo server, and open a NEW window to https://localhost:4200
echo ===================================================
pause

Notes

  • Make sure your package.json uses --host=localhost (not 127.0.0.1) in the start:windows / start:default scripts — some services (like Facebook's JS SDK) distinguish between the two hostnames.
  • The exported cert file name matches your app's package.json "name" field, not always "localhost" itself.

This applies to any Angular + ASP.NET Core project using the standard SPA HTTPS dev-cert setup, not just this one.
