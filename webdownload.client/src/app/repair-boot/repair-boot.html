Windows 11 Boot Repair Guide

January 3, 2026

Restore bootability to a non-bootable Windows 11 hard disk with intact OS and data

Scenario

Problem: First hard disk contains current Windows 11 installation with up-to-date data and applications, but is not bootable (missing boot partition or boot files).

Available: Second hard disk that is bootable (cloned from first disk in the past via Acronis).

Goal: Make the first hard disk bootable again without reinstalling Windows or losing data.

Prerequisites

  • Administrator access to Windows
  • Both hard disks connected to the system
  • Boot from the working (second) hard disk
  • Basic familiarity with Command Prompt
⚠️ Important Safety Notice

Before proceeding, back up any critical data from the first disk if possible. While this procedure is safe, it's always better to have backups.

Step-by-Step Procedure

Step 1 Identify Disk Volumes

Open Command Prompt as Administrator and run diskpart to view all volumes:

diskpart
list volume

Look for the following in the output:

Volume Type Characteristics Purpose
Current Boot Disk Status: "Boot" (usually C:) Currently booting system (second disk)
EFI System (Current) FAT32, 100MB, Status: "System" Boot partition for second disk
Target Disk NTFS, Large partition with data First disk to be made bootable
EFI System (Target) FAT32, 200MB, Hidden Boot partition for first disk

Step 2 Assign Drive Letter to Target EFI Partition

Identify the EFI partition belonging to your first disk (the one to be made bootable). In diskpart:

select volume 5
// Replace '5' with the actual volume number of the first disk's EFI partition
detail volume
// Verify this is the correct EFI partition for the first disk
assign letter=T
exit
Note: The EFI partition is usually 100-500MB, formatted as FAT32, and marked as Hidden. Use "detail volume" to confirm which physical disk it belongs to.

Step 3 Identify Windows Installation on First Disk

Determine which drive letter contains the Windows installation on your first disk:

dir D:\Windows
dir F:\Windows
// Check each potential drive until you find the Windows folder

The drive that shows a Windows directory is your target. In this example, we'll assume it's D:

Step 4 Copy Boot Files to First Disk's EFI Partition

Use the bcdboot command to install boot files from the first disk's Windows installation to its EFI partition:

bcdboot D:\Windows /s T: /f UEFI

Where:

  • D:\Windows = Path to Windows installation on first disk
  • /s T: = Target EFI system partition (assigned in Step 2)
  • /f UEFI = Format for UEFI boot (modern systems)
Expected Output: "Boot files successfully created."

Step 5 Verify Boot Configuration

Confirm that the boot entry was created successfully:

bcdedit /enum firmware

Look for an entry showing:

  • device = partition=T: (or the letter you assigned)
  • path = \EFI\Microsoft\Boot\bootmgfw.efi
  • description = Windows Boot Manager

Step 6 Test the Bootable Disk

Option A: Physical Disk Test (Recommended)
  1. Shut down the computer completely
  2. Physically disconnect the second (working) hard disk
  3. Leave only the first disk connected
  4. Power on the computer
  5. The first disk should now boot successfully
Option B: BIOS Boot Order Change
  1. Restart the computer
  2. Enter BIOS/UEFI settings (F2, F10, DEL, or F12)
  3. Navigate to Boot menu
  4. Look for two "Windows Boot Manager" entries
  5. Move the first disk's entry to top priority
  6. Save and Exit

Verification Checklist

Check Expected Result
Windows boots successfully System starts without errors
All data is accessible Files and folders are intact
Applications are present Installed software appears in Start Menu
System settings preserved User accounts, preferences intact

Troubleshooting

  • Verify you selected the correct EFI partition using "detail volume" in diskpart
  • Ensure the Windows path was correct (check for \Windows folder)
  • Try running the bootrec commands:
bootrec /fixmbr
bootrec /fixboot
bootrec /rebuildbcd

  • The first disk may not have an EFI partition - it might have been deleted
  • You may need to create a new EFI partition using diskpart
  • Alternatively, clone the EFI partition from the second disk

  • Ensure Command Prompt is running as Administrator
  • Disable BitLocker if enabled on the disk

Technical Notes

About EFI System Partitions

The EFI System Partition (ESP) is a small FAT32 partition that contains boot loaders and boot configuration files. In UEFI systems, this partition is essential for booting Windows. The bcdboot command copies the necessary boot files from a Windows installation to the ESP.

Drive Letter Changes After Boot

When you boot from the first disk alone, the drive letters will change. What was previously D: will likely become C: since it's now the boot drive. This is normal Windows behavior.

Commands Reference

Command Purpose
diskpart Disk partitioning utility
list volume Display all volumes with details
select volume # Select a specific volume for operations
detail volume Show detailed information about selected volume
assign letter=X Assign drive letter to selected volume
bcdboot [source] /s [target] /f UEFI Copy boot files from Windows installation to EFI partition
bcdedit /enum firmware Display firmware boot entries

Success Indicators

If you successfully completed this procedure, you should have:

  • A bootable first hard disk with all current data and applications
  • Avoided reinstalling Windows and all software
  • Created proper EFI boot files on the first disk
  • A backup bootable disk (the second one) for emergency use
